# View notes

- **Every button is a `ViewButton` instance** (`Assets/Resources/Prefabs/UI/Buttons/ViewButton.prefab`), nested inside the screen prefabs. Look and feel (sprite, tint states, `ButtonFeedback` hover settings) come from `ViewButton`; edit it there. New buttons: drag in `ViewButton`, don't build one from scratch.
- Per-instance overrides are expected only for layout and content: RectTransform, label text/size/margins, `pixelsPerUnitMultiplier`, and `onClick`. Don't set `ButtonFeedback` or `Button.colors` on instances; that creates overrides in the screen prefab that mask the base. If they creep in, revert per property with `PrefabUtility.RevertPropertyOverride`.
- Most `onClick` handlers are wired **in the scene** (targets on `GameHandler`), not in the screen prefabs, because the targets live in the scene. Replacing a button object loses that wiring; re-add it with `UnityEventTools.AddPersistentListener`.
- `DeckViewer.MyButton` references the scene's `MyDeckButtonScreen/DeckButton`. `TutorialSpotlight` finds End Turn by its label text "End Turn", so keep that label.
- One `ButtonFeedback` per button. Duplicates fight over the label colour every frame.

## Highlights

- Two glow components: `CardHighlightEffect` (cards, trinkets/`ViewBuff`, starter bundles; sprite-based "mist" shader) and `MeshHighlightEffect` (3D: player portraits, ritual altars, Styx trinkets).
- **The inspector's `settings` preset is what plays.** Both components copy it into their glow fields on `Awake` (and every frame in the editor while glowing, so preset edits show live in play mode). The custom inspectors show the preset inline and hide the mirrored fields. Code never writes `settings`. Assigned presets: bundle = ChoiceLarge (band widened in the prefab: glow sprites scaled up, 9-slice size scaled down), trinkets (`ViewBuff.prefab`) = Choice, portraits (`ViewPlayerPortrait`) = TargetMesh, altars = AltarFlame (see below), Styx trinkets = Hammer1/Shears1 (scene overrides, `Assets/Settings`).
- **Only cards switch preset at runtime**, because their state changes: `ViewCard.SetHighlight(bool, HighlightState)` picks from `HighlightPalette` (`Resources/Content/HighlightSettings`: Follower, Spell, Target, Choice) and calls `CardHighlightEffect.UsePreset`, which sets a runtime-only live preset (`LivePreset`); the inspector shows which one is playing. Selected = Ready preset × `SelectedIntensity` via `IntensityScale`.
- Combat state decisions live in `ViewBattleRow.RefreshPositions` (per-frame: attacker = Selected, attack/spell/ritual targets = Target, can-attack = Ready) and `View.HighlightTargets` / `ViewBattleRow.HighlightTargets` (Target). Hand cards: `ViewHandHandler` (Ready; the spell being aimed, `SelectionHandler.HeldCard`, stays in hand as Selected). Out-of-combat callers pass `HighlightState.Choice` (rewards, shop, temple, deck selection).
- Ritual altars burn with `AltarFlame` (not `MeshHighlightEffect`) plus `RitualOutlineHighlight` (Linework layer 8) colours.

## Combat board

- `View.LoadBackground` picks the encounter's ground (`Background`) and lane (`AIBattleRow`, `PlayerBattleRow`) materials under `NewBackgroundHolder`. Lanes are 60x0.2x10 slabs sunk to y = -0.09 so their side face doesn't show as a dark line.
- `LaneEdge` (on each lane) draws the carved edge with `Graphics.DrawMesh` from the lane mesh bounds: no child objects, runs in edit mode. Tune it via its fields and `LaneEdge.mat` (transparent Lit, queue 2950 so card glows draw over it).
- Portrait frame: `ViewPlayerPortrait.prefab/PortraitFrame` is still an instance of the old `PortraitFrame.fbx` with its mesh and material overridden to `PortraitFrameTerracotta` (the mesh faces +Z, so the frame is rotated 180° in Y). Its placement is tuned in `ViewPlayer.prefab` overrides. The health seal (`GameObject/Health`) sits on the frame's bottom band so it clears the hand. Its `MeshHighlightEffect` builds the target-glow shells from that mesh (two extra copies). The frame currently ships at full Meshy detail (1.95M tris, ~75 MB FBX) because the 58k decimation looked visibly softer; a performance pass may revisit this.
- Meshy models: the raw export's smoothed custom normals are what make it look clean; plain decimation exposes lumpy geometry on glossy glaze. Use `Tools/Blender/meshy_decimate.py` (ratio 1 = full detail, just renamed), and keep the mesh name stable across re-exports (the FBX sub-asset ID comes from it, so a rename breaks prefab references).
- Drop target: while a playable follower is held and the row has room, `ViewBattleRow.Update` calls `LaneEdge.SetHighlight`; the bevel glows with `LaneEdgeGlow.mat` (additive) in the Target preset's colour, pulsing at its speed, and goes steady and brighter while the cursor is over the lane. The old flat `ViewBattleRow.Highlight` sprite is only a fallback when no LaneEdge is assigned.
- Discard: `ViewDiscard` (scene, `Player Discard`, layer 7 BoxCollider for drops) drives `DiscardBowl.SetHighlight` on the bowl prefab: an additive ring drawn with Graphics.DrawMesh at the rim (bowl-local radii; the bowl's opening faces local +Z) plus a MaterialPropertyBlock brightening of the label. The old flat `Plane`/label are inactive and `Highlight` is only a fallback. Lane and bowl share the fade/pulse timing in `DropGlow`.
- `CurvedText` bends any TextMeshPro along an arc by rewriting vertices on `TEXT_CHANGED_EVENT`; edit text, font, size and colour on the TMP component as usual. Its pivot is the top of the arc (centre/baseline alignment).

## Ritual altars

- Every altar (`ViewRitual3` → `Altar2` child) uses the generated `AltarKit.fbx` with four material slots (Stone, Panel, Trim, Corner). `ViewRitual.Refresh` → `ApplyAltarStyle` swaps in the ritual's `AltarStyle` (`Resources/Content/AltarStyles/<God>/<God>.asset`, god from `Ritual.God`, fallback Default) and sets the rules text colour. Full guide: `Docs/AltarKit.md`.
- Ready glow on kit altars: `AltarFlame` on `Altar2` draws a ring of flame quads rising from the altar's footprint (Graphics.DrawMesh, shader `Pharmakos/AltarFlame`, material `Models/Materials/AltarFlame.mat`). `ViewRitual.SetHighlight` lights it; `UpdateSpotlight` turns it off again whenever the ritual isn't usable, so to preview it in a test call `AltarFlame.SetActive(true)` directly. The old shell-based `MeshHighlightEffect` (inflated copies of the mesh) is kept only as a fallback for non-kit altars; on the clean kit mesh it missed sides and bled onto the cost icons.
- `AltarContactShadow` (also on `Altar2`) draws a soft dark ring on the ground round the footprint, reusing `AltarFlame.Footprint`/`BaseHeight` via `AltarFlame.BuildRing`. It needs the `AltarFlame` component on the same object.
- Altar textures are regenerated by `Tools/Blender/altar_textures.py`: pass an absolute output path, then force a reimport of `Resources/Content/AltarStyles` (a plain refresh can leave the old textures in place).
- Hover and use-pulse scaling (`UpdateHoverScale`) act on the altar root (`Altar2`) only, never the `ViewRitual` root: scaling the root moved the child `Spot Light` away and dimmed it. The root's scale belongs to `SetDisplayScale`.
- **TMP colours in Linear space:** TMP 3.0.7's shaders use vertex colours unconverted, so in this Linear project a text colour renders lighter than set (dark colours most: `#3F0000` shows as `#820000`). `ViewRitual.ApplyAltarStyle` converts the altar style's `TextColor` to linear so altars match the hex; other TMP text in the game was tuned by eye under the old behaviour and is left alone.
- `ScreenCapture` right after changing TMP text can capture the frame before the text mesh rebuilds (text missing); capture again a frame later.
